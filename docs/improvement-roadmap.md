# Stratum V3 Relay 改进路线

本文记录代码审查发现的后续改进事项，便于维护人员按风险和收益安排版本。完成一项后，应同时补充自动测试、升级说明和回滚办法。

## 已完成

- [x] Tailscale 面板增加“运维问题中心”：集中读取关键 VPS 服务状态和最近 24 小时日志，把常见问题转换成中文原因与处理建议；同类日志合并，已经恢复的问题不再列为待处理，原始日志可折叠查看。
- [x] 增加独立 HTTPS 公网只读面板：公网进程只提供汇总状态和脱敏事件，没有写接口，也不读取或展示 Worker、矿机 IP、上游地址、密钥、证书、审计与原始日志；完整后台继续限制在 Tailscale。

## P1：优先处理

### 配置和同步文件增加跨进程锁（已完成）

管理面板、自动试切和双 VPS 同步都会执行“读取、修改、覆盖写入”。原子替换可以避免半写文件，但不能阻止两个进程基于同一旧版本分别写入，后写入的一方可能覆盖另一方的线路、试切状态或同步任务。

实现：

- 配置存储使用文件锁和进程内线程锁保护读写，兼容 Linux 生产环境与 Windows 测试环境。
- 主配置保存时递增 `generation`；旧副本写入会提示刷新重试，不再覆盖较新的线路或试切设置。
- 同步 outbox 和 peer state 使用同一把锁，审计 JSONL 的追加与裁剪也已串行化。
- 自动测试覆盖两个写入者基于同一版本修改时的冲突路径。

### 双 VPS 同步改用逻辑版本（已完成）

当前同步版本来自各 VPS 的系统时间。时钟漂移可能让合法更新长期被判定为旧事件；异常的大时间值也会阻止后续正常同步。

实现：

- 每台 VPS 首次同步时生成持久节点 ID，每个端口独立递增序号；系统时间不再参与新版本的先后判断。
- 事件时间偏差超过 5 分钟时只记录偏差秒数供审计，不会阻止后续正常同步。
- 保存各节点已见序号和对端确认结果；管理首页显示待发送、已确认和冲突数量。
- 滚动升级期间仍接收旧版 `revision`，但旧时间版本放在独立命名空间，无法压制新逻辑版本。

### 降低公网 TLS 服务权限

公网加密入口目前以 root 运行。systemd 已经启用基础隔离，但网络服务出现解析漏洞时仍可能拥有过大的读取权限。

建议：

- 使用独立服务用户运行加密入口。
- 低端口通过 `CAP_NET_BIND_SERVICE` 授权。
- 配置和证书设置为组只读，只允许写入专用状态目录。
- 管理面板逐步拆分为普通 Web 服务和只接受固定操作的特权助手。

## P2：工程质量

### 建立统一测试入口和持续集成

目前 Python 测试依赖从特定子目录启动，从仓库根目录执行标准发现命令可能得到“0 tests”。

建议：

- 测试数据路径基于测试文件所在目录，不依赖当前工作目录。
- 在仓库根目录提供统一的 Windows 和 Linux 测试命令。
- 使用 GitHub Actions 运行 Python 测试、Windows C# 编译、客户端核心测试和配置渲染检查。
- 明确支持的 Ubuntu、Python 和 .NET Framework 版本，并固定依赖范围。

### 改进版本和发布流程

客户端版本目前同时出现在 C#、Python、测试和文档中，历史 EXE 也直接保存在 Git 历史里。

建议：

- 使用单一版本来源生成各组件显示版本。
- 将二进制放入 GitHub Releases，由自动流程构建、签名并生成 SHA-256。
- 发布前验证签名、版本、测试结果和升级回滚步骤。
- 在安装内部代码签名证书前，清楚提示它会修改 Windows 系统级信任存储。

## P3：安全和维护性

- 为应急密码登录增加失败次数限制和短时冷却。
- HTTPS 访问启用 Secure Cookie，并统一增加 CSP、禁止嵌入和 MIME 类型保护响应头。
- `PANEL_SECRET_KEY` 缺失时拒绝启动，避免重启后会话密钥随机变化。
- 按认证、配置、同步、监控和页面拆分管理面板的大型单文件。
- 按中转核心、状态统计、配置存储和界面拆分 Windows 客户端源码。
- 如果项目供外部人员使用，增加 `LICENSE`、`SECURITY.md` 和漏洞报告方式。

## 验收原则

每项改进至少满足：现有生产行为不变、自动测试覆盖故障路径、升级失败可以回滚、面板提示适合非技术管理员、日志和错误信息不泄露共享密钥或矿池密码。

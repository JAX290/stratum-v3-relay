# Stratum V3 Relay 改进路线

本文记录代码审查发现的后续改进事项，便于维护人员按风险和收益安排版本。完成一项后，应同时补充自动测试、升级说明和回滚办法。

## 已完成

- [x] Tailscale 面板增加“运维问题中心”：集中读取关键 VPS 服务状态和最近 24 小时日志，把常见问题转换成中文原因与处理建议；同类日志合并，已经恢复的问题不再列为待处理，原始日志可折叠查看。
- [x] 增加独立 HTTPS 公网只读值守面板：使用独立账号密码和登录限流；登录后显示矿机 IP、Worker、Share、上游线路、端口、服务和脱敏事件，没有配置写接口，也不读取或展示共享密钥、密码、Webhook、证书私钥与未经脱敏的原始日志；完整后台继续限制在 Tailscale。

## P1：优先处理

### 配置和同步文件增加跨进程锁（已完成）

管理面板、自动试切和双 VPS 同步都会执行“读取、修改、覆盖写入”。原子替换可以避免半写文件，但不能阻止两个进程基于同一旧版本分别写入，后写入的一方可能覆盖另一方的线路、试切状态或同步任务。

实现：

- 配置存储使用文件锁和进程内线程锁保护读写，兼容 Linux 生产环境与 Windows 测试环境。
- 主配置保存时递增 `generation`；旧副本写入会提示刷新重试，不再覆盖较新的线路或试切设置。
- 同步 outbox 和 peer state 使用同一把锁，审计 JSONL 的追加与裁剪也已串行化。
- 自动测试覆盖两个写入者基于同一版本修改时的冲突路径。

### 双 VPS 同步改用逻辑版本（已完成）

当前同步版本来自各 VPS 的系统时间。时钟漂移可能让合法更新长期被判定为旧事件；异常的大时间值也会阻止后续正常同步。

实现：

- 每台 VPS 首次同步时生成持久节点 ID，每个端口独立递增序号；系统时间不再参与新版本的先后判断。
- 事件时间偏差超过 5 分钟时只记录偏差秒数供审计，不会阻止后续正常同步。
- 保存各节点已见序号和对端确认结果；管理首页显示待发送、已确认和冲突数量。
- 滚动升级期间仍接收旧版 `revision`，但旧时间版本放在独立命名空间，无法压制新逻辑版本。

### 降低公网 TLS 服务权限（已完成）

公网加密入口目前以 root 运行。systemd 已经启用基础隔离，但网络服务出现解析漏洞时仍可能拥有过大的读取权限。

实现：

- 加密入口改由独立的 `stratum-relay` 系统账户运行。
- 仅保留绑定低端口需要的 `CAP_NET_BIND_SERVICE`，并收紧设备、内核、控制组、文件系统和地址族访问。
- 配置、证书和私钥归 `root:stratum-relay`、权限 `0640`；服务只能写自己的状态目录。
- 新安装直接使用低权限服务，已有 VPS 执行面板升级脚本时会自动迁移证书、配置、状态目录和 systemd 单元。
- 完整管理面板的特权助手拆分留在后续维护性工作中继续处理。

## P2：工程质量

### 建立统一测试入口和持续集成（已完成）

Python 测试现在可以从仓库根目录启动，不再依赖当前工作目录。

实现：

- 测试数据路径全部基于测试文件位置。
- 根目录提供 `test.ps1` 和 `test.sh` 统一入口。
- GitHub Actions 自动运行 Python 测试、Linux 配置渲染与脚本检查、Windows C# 编译和客户端核心测试。
- CI 基线为 Ubuntu 24.04 / Python 3.12 与 Windows Server 2022 / .NET Framework，Python 开发依赖使用有上限的版本范围。

### 改进版本和发布流程（已完成）

客户端版本目前同时出现在 C#、Python、测试和文档中，历史 EXE 也直接保存在 Git 历史里。

实现：

- 根目录 `version.json` 是面板、TLS 服务和 Windows 客户端的唯一版本来源。
- `client-vX.Y.Z` 标签触发发布工作流；流程会测试、构建、签名、验证 Authenticode、生成 SHA-256 并创建 GitHub Release。
- 缺少签名凭据、版本标签不一致、测试或签名失败时拒绝发布。
- 内部证书安装脚本会先说明它将修改 Windows 系统级信任存储，并要求明确输入 `INSTALL`。
- 具体操作和 CI 签名证书要求见 `docs/releasing.md`。

## P3：安全和维护性

- [x] 应急密码登录 5 分钟内失败 5 次后冷却 15 分钟；成功登录会清除失败记录。
- [x] HTTPS 访问动态启用 Secure Cookie，并统一增加 CSP、禁止嵌入、MIME 类型、来源信息和 HSTS 保护头；SSH 本地 HTTP 隧道仍可登录。
- [x] `PANEL_SECRET_KEY` 缺失时拒绝生产启动，避免重启后会话密钥随机变化。
- [x] 管理面板按职责拆分：认证与限流位于 `admin_auth.py`，配置存储与渲染位于 `v3_manager.py`，后台同步执行位于 `route_switch_monitor.py`，监控由独立 inspector/monitor/watchdog 进程负责，页面使用独立模板和静态文件；主文件保留路由编排与页面上下文。
- [ ] 按中转核心、状态统计、配置存储和界面拆分 Windows 客户端源码。（进行中：服务器配置、端口映射、DPAPI 密钥保护和本地配置存储已迁入 `ConfigModels.cs`，构建脚本已支持多源码文件。）
- [x] 公开仓库采用 MIT License；`SECURITY.md` 已说明支持范围、GitHub 私密漏洞报告入口、响应目标及敏感信息脱敏要求。
- [x] 仓库根目录提供统一 `deploy.sh`：自动区分首次安装和保留配置升级，更新代码前拒绝覆盖本地修改，串联 V3、TLS、Tailscale 和公网值守面板，并在失败时显示步骤、备份位置和重试方法。

## P4：非技术管理员的一键运维

### 管理界面减负与通知渠道（已完成）

- [x] 矿机页优先显示当前有连接或活跃 Worker 的矿池，同时显示实际使用端口；未使用矿池默认折叠。
- [x] 设置页增加分区导航，减少在长页面中查找客户端、通知、提醒、模板、探测和同步设置的成本。
- [x] 支持在 Tailscale 管理面板配置、清除并测试企业微信、钉钉和 SMTP 邮箱通知，敏感值保存后不回显。

后续管理体验改进优先考虑：通知发送状态和最近失败原因、按严重级别选择通知渠道和免打扰时段、跨 VPS 的统一健康摘要，以及常用线路收藏。此处为计划，不代表当前版本已经提供。

这一阶段以“管理员不需要登录 VPS、不需要复制命令、不需要理解 systemd、端口或证书术语”为验收标准。页面先说清楚影响了哪个矿场、多少矿机和是否仍在出 Share，再提供处理动作。

### 一键全面诊断

- [ ] 在 Tailscale 管理面板首页增加“一键全面诊断”，统一检查 VPS 服务、TLS 入口、证书有效期、磁盘和内存、端口监听、HAProxy 配置、矿池连通性、双 VPS 同步、Windows 心跳、客户端版本和最近 Share。
- [ ] 诊断结果按“运行正常 / 系统已自动恢复 / 可以一键修复 / 需要人工处理”分组，不把原始日志作为管理员看到的第一层内容。
- [ ] 每个问题显示业务影响，例如“二号矿场 18 台矿机已 6 分钟没有 Share”，并标出首次发生时间、是否仍在持续和系统已经尝试过什么。
- [ ] 生成自动脱敏的“技术支持包”，包含版本、健康检查、配置摘要和相关日志；下载前再次扫描共享密钥、Webhook、矿池密码和真实公网资料，管理员可以直接发给技术人员。

### 一键安全修复

- [ ] 为可逆且低风险的问题提供“一键修复”：只重启异常服务、重试双 VPS 同步、重新加载已验证配置、清理本项目过期日志、重新运行健康探测。
- [ ] 修复前自动备份相关配置，页面明确显示将执行的动作和预计影响；修复后自动重新诊断，并显示“已恢复”或“未解决”。
- [ ] 修复失败时自动恢复本次备份；同一问题连续修复失败后停止重试，防止中转反复断线。
- [ ] 线路切换、证书更换、防火墙开放和 DNS 修改使用分步骤向导。系统先检测候选方案，只有验证成功后才显示最终执行按钮。
- [ ] 所有诊断、修复、验证和回退写入审计时间线，记录操作者和结果，但不记录密钥或密码。

### Windows 值守电脑自助维护

- [ ] 把现有“一键诊断”升级成“一键检查并修复”，可处理程序未启动、配置格式错误、监听端口冲突、Windows 防火墙规则缺失、主 VPS 不通但备用可用、版本过旧等常见问题。
- [ ] 需要管理员权限的 Windows 操作只在执行该项修复时请求授权，并用中文说明将修改什么；普通诊断不弹权限提示。
- [ ] 增加“值守模式”首页，只保留一个总状态、受影响矿机数量、“检查并修复”和“联系技术人员”四类关键信息；高级参数放入单独页面。
- [ ] 增加客户端配置备份和恢复向导。恢复时先校验证书指纹、密钥格式和 VPS 连通性，成功后才替换正在使用的配置。

### 主动提醒和维护闭环

- [ ] 企业微信告警直接包含通俗原因、影响范围、面板问题编号和“打开处理页面”链接；恢复后发送同一问题的闭环消息，避免管理员反复确认。
- [ ] 增加证书、磁盘、客户端版本和长期无 Share 的提前提醒，并区分“今天处理 / 本周处理 / 仅供参考”。
- [ ] 首页提供每日自动巡检结论和最近 7 天稳定性摘要；全部正常时只显示一句结论，不要求管理员阅读图表或日志。
- [x] 公网 HTTPS 只读面板使用独立账号密码，可显示值守所需详细状态但不提供任何修复按钮；所有修复动作只允许从 Tailscale 管理面板执行。

### 实施顺序

1. 先实现 VPS 一键全面诊断、统一问题编号和脱敏支持包。
2. 再实现“重启单个异常服务、重试同步、重新探测”三类低风险修复，并完成修复后的自动验证与回退。
3. 然后升级 Windows 客户端的一键检查和修复。
4. 最后增加线路、证书、DNS 和升级向导，以及企业微信处理链接和周期巡检。

## 验收原则

每项改进至少满足：现有生产行为不变、自动测试覆盖故障路径、升级失败可以回滚、面板提示适合非技术管理员、日志和错误信息不泄露共享密钥或矿池密码。一键修复还必须满足：动作范围明确、执行前有备份、执行后有验证、失败能够回退、重复失败会停止并转交人工。

# 后续更新计划与进度

本文是本项目后续开发计划的唯一记录。README 只说明当前已经实现的功能；尚未实现、正在实现和已经完成的改进都在这里维护。

最后更新：2026-09-22

## 状态说明和维护规则

| 状态 | 含义 |
| --- | --- |
| ✅ 已完成 | 功能已经合入 `main`，升级后可用，并完成必要测试和文档 |
| 🟡 进行中 | 已开始设计或开发，但不能视为生产可用 |
| ⬜ 计划中 | 已确认需要实现，尚未开始 |
| ⏸ 暂缓 | 保留需求，当前阶段不实施 |

每次开始或完成一项工作时，都必须更新本文件：

1. 使用固定编号，避免讨论中名称变化后重复立项。
2. 开始开发时将状态改为“进行中”，写明本次范围。
3. 合入 `main` 后改为“已完成”，补充完成版本、日期和验证结果。
4. 如果只完成一部分，保留“进行中”，在进展栏明确已经完成和仍未完成的内容。
5. 新需求先归入“VPS 端”或“Windows 客户端”，再安排优先级和实施顺序。
6. 自动修复类功能必须同时具备：执行前说明、配置备份、执行后验证、失败回退和连续失败停止机制。

优先级含义：P1 直接影响稳定性或非技术管理员处理故障；P2 明显改善维护效率；P3 属于长期体验和架构优化。

## 共用验收原则

每项改进至少满足：

- 现有生产行为保持兼容，升级已有 VPS 或客户端时保留配置；
- 自动测试覆盖成功、失败和回退路径；
- 升级失败可以回滚，不能留下半套配置；
- 页面先说明影响哪个矿场、多少矿机、是否仍有接受 Share，再显示技术细节；
- 日志、通知和导出文件不泄露共享密钥、Webhook、矿池密码或证书私钥；
- 涉及断线风险的操作必须明确提示影响范围，并提供验证或恢复手段。

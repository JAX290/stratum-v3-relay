# 管理员完整使用说明

本指南面向不熟悉程序、Linux 或网络命令的管理员，说明如何进入系统、怎样判断是否正常、每个页面和折叠内容代表什么，以及哪些操作可能影响矿场。功能概览见[项目首页](../README.md#功能说明)，安装及 VPS 命令排障见[部署与维护指南](deployment-guide.md)。

## 使用顺序

1. 先阅读“选择访问入口”和“应急管理密码”。
2. 日常打开“总览”，按管理员结论判断是否需要处理。
3. 需要找具体矿机时进入“矿机”，按需展开折叠内容。
4. 只有确认目标线路正确后才进入“线路与端口”修改。
5. 接入电脑、通知和双 VPS 同步统一在“设置”处理。
6. 页面提示异常时进入“日志”，先看中文建议，再决定是否展开技术详情。

## 选择访问入口

- **查看生产状态**：打开 HTTPS 状态域名，使用值守账号密码登录，无需 Tailscale。此入口只读。
- **配置矿池、接入客户端、管理矿场**：连接 Tailscale，打开管理面板地址。
- **查看 VPS 日志原因与处理建议**：在管理面板打开“日志 → 运维问题中心”。需要技术协助时展开原始日志。

管理面板地址由部署脚本和 `tailscale serve status` 输出；HTTPS 状态域名由管理员配置。两者用途不同，不能互相替代。

### 三种登录凭据不是同一个密码

| 凭据 | 什么时候使用 | 能做什么 |
| --- | --- | --- |
| Tailscale 身份 | 日常管理的首选方式 | 进入完整管理面板；可以打开客户端接入资料和通知渠道等敏感区域 |
| 应急管理密码 | Tailscale 暂时无法使用，但仍能通过 SSH 登录 VPS 时 | 通过 SSH 隧道临时进入管理面板，检查状态、线路和日志；不能打开只允许 Tailscale 访问的敏感资料 |
| HTTPS 值守账号和密码 | 不安装 Tailscale、只查看状态时 | 进入公网只读面板；不能修改任何配置 |

这些凭据与 VPS 的 `root` 密码、Windows 客户端共享密钥、矿池账号密码都没有关系。

## 应急管理密码

### 它是什么

应急管理密码是完整管理面板的备用登录密码。正常通过 Tailscale Serve 打开管理面板时，系统使用已经验证的 Tailscale 身份自动登录，不会询问这个密码。安装时直接回车留空，表示关闭应急密码登录，不影响 Tailscale 日常管理。

### 什么时候会用到

只有同时满足以下情况才需要它：

- Tailscale 服务、登录或 MagicDNS 暂时异常，正常管理地址打不开；
- VPS 的 SSH 仍然能够连接；
- 管理员需要临时查看完整面板或调整普通线路配置。

从 Windows 建立隧道：

```powershell
ssh -N -L 8789:127.0.0.1:8789 -p <SSH端口> root@<VPS公网IP>
```

保持 PowerShell 窗口开启，在浏览器打开 `http://127.0.0.1:8789`，输入应急管理密码。这个过程把本机浏览器安全地连接到 VPS 内部面板，不需要也不应该把 `8789` 端口开放到公网。

应急登录是临时维护入口。通过它不能查看客户端共享密钥，也不能修改通知渠道；这些敏感功能仍要求请求经过 Tailscale Serve。连续输错 5 次会暂停 15 分钟。

忘记密码时，通过 SSH 在 VPS 执行：

```bash
/opt/stratum-admin/reset-panel-password.sh
```

只使用 Tailscale、希望关闭应急密码时执行：

```bash
/opt/stratum-admin/reset-panel-password.sh --disable-password
```

## 页面数据和折叠内容怎样理解

### 折叠的基本原则

页面把低频信息折叠起来，是为了让管理员先看到正在生产和需要处理的内容。**折叠只改变网页显示，不代表对应矿池、Worker、监控或告警被停用，也不会改变任何线路。** 点击带三角形或“查看……”的标题即可展开，再点一次收起。

线路修改等操作采用局部刷新。完成后页面保持原来的滚动位置，之前展开的区域也尽量保持展开；右上方会显示成功或失败结果。

### 矿池为什么会被收起

- 当前有连接或在线 Worker 的矿池优先完整显示。
- 当前连接数为 0，并且在线 Worker 数为 0 的矿池放进“未使用的矿池”。
- 未使用矿池仍可能保存以前的 Worker、Share 和断线记录，需要追查历史时再展开。
- 矿池被收起不等于删除，也不等于地址探测停止。

### Worker 为什么会分组

系统先按“同一矿池中的完整 Worker 名称”汇总。一个 Worker 可能从多个来源 IP、端口或连接出现，所以卡片显示合计值；点击“查看同名矿工明细”后，才能看到每条连接的线路、来源 IP、矿机软件、连接时间、Share、拒绝率和响应时间。

状态按最后连接时间分类：

| 状态 | 判定 | 默认显示方式 |
| --- | --- | --- |
| 在线 | 当前仍有至少一条连接 | 直接显示 |
| 最近断开 | 已无连接，但断开不足 15 分钟 | 与在线 Worker 一起直接显示，便于观察短暂重连 |
| 离线 | 已无连接超过 15 分钟，但不超过 24 小时 | 默认折叠 |
| 失效 | 已无连接超过 24 小时 | 默认折叠，主要用于历史追查 |

如果同名 Worker 有多条明细，只要其中一条仍在线，汇总卡片会优先显示较好的状态；因此排查“为什么连接数不一致”时应展开明细逐条查看。

### 常见统计的原理

- **矿机数**：按 Windows 客户端上报的不同局域网 IP 统计，一台矿机多条连接仍算一台。
- **连接数**：当前通过中转建立的连接数量，可能大于矿机数。
- **提交 / 接受 / 拒绝**：检查器观察到的 Share 计数；“有连接”但长期没有接受 Share，仍需要检查。
- **拒绝率**：拒绝 Share 数除以提交 Share 数。短时间样本很少时会波动，应同时看持续时间和矿池反馈。
- **估算算力**：根据观察到的 Share 难度和时间估算，只用于运维判断，不能代替矿池结算页面。
- **响应时间**：VPS 到上游矿池或 Share 往返的观测值，用于比较线路，不代表矿场局域网的全部延迟。

## 各页面怎样使用

### 总览

先读顶部“管理员结论”，再看预计受影响矿机数和建议。随后按顺序检查：

1. 当前连接、在线矿工、最近断开、离线/失效、拒绝率和报警数。
2. 核心服务是否全部为 `active`。任何一项不是 `active` 都应进入“日志”查看原因。
3. 矿场运行总览中的客户端心跳、矿机数、连接数、版本和最后上报时间。
4. 版本统一、到期提醒、线路摘要和最近操作时间线。

绿色表示当前检查正常；黄色表示可以运行但需要关注；红色表示已有明确异常。颜色是排查入口，最终是否正常仍以矿机持续出现“接受 Share”为准。

### 矿机

用于回答“哪个矿池、哪个 Worker、哪台来源 IP 有问题”。先看直接显示的生产矿池，再展开离线、失效或未使用矿池。不要仅凭 Worker 名称判断物理矿机；需要展开同名明细核对来源 IP 和端口。

### 线路与端口

每一行代表矿机连接的一个 VPS 端口及其当前上游矿池。普通修改应先“只检测，不切换”，再选择一台正在使用该端口的矿机进行 10 分钟单机测试。测试通过后系统才自动全量切换；失败会把测试矿机退回原线路。

“已验证地址直接切换”会让该端口上的矿机重连，只用于已经完成测试的地址。“恢复上一次”和历史恢复同样会影响对应端口。双 VPS 同步开启后，页面会等待对端确认并显示结果；对端离线不影响本机已经完成的修改，任务会保留并重试。

### 报警

查看当前矿池地址异常、阈值和通知结果。报警表示监控发现异常条件，不一定代表所有矿机已经掉线；应结合总览的连接、接受 Share 和影响矿场判断优先级。

### 设置

- **客户端与矿场**：新增、改名、删除矿场及复制 Windows 接入资料。敏感资料只允许通过 Tailscale 查看。
- **通知渠道**：企业微信、钉钉和邮箱各支持最多 3 个目标。保存后必须逐项发送测试。
- **到期提醒**：记录 VPS 和域名到期日；TLS 证书日期自动读取。
- **矿池模板**：维护成组的主、备用地址。修改模板本身不等于立即切换所有正在运行的端口。
- **探测策略**：控制后台检查频率。矿池限制探测时可降低频率，手动检测仍可使用。
- **双 VPS 同步**：显示最近结果、反馈时间、待重试任务和已确认端口。不要在两台 VPS 同时执行“以本机为准”的全量同步。

### 日志

先看“管理员处理清单”的中文原因和建议。同类重复日志会合并，已经明确恢复的问题不再占据待处理列表。“查看技术详情”和“最近 24 小时全部服务日志”默认折叠，因为它们主要供技术人员定位；展开不会执行任何命令，也不会改变服务。

配置审计记录谁在何时修改了什么，不记录密钥内容。最近 7 天断线明细用于追查历史；配置回滚会改变实际线路，使用前必须核对备份时间和影响端口。

## 日常值守

Windows 客户端从 `2.3.0` 起保留原桌面版操作，并支持无需用户登录的服务模式。升级不会要求重新填写 VPS、密钥或端口。测试构建不应直接替换生产程序。

### Windows 无人值守服务

从当前 `client-v2.3.2` 发布页下载签名的 `MulinSenRelayService-2.3.2.exe` 与 `install-service-2.3.2.ps1`，放在同一目录。若“文件属性 → 数字签名”尚未显示签名有效，同时下载并解压 `publisher-certificate-tools-2.3.2.zip`，核对固定指纹后先运行其中的内部发布者证书安装脚本。随后以管理员身份打开 Windows PowerShell：

```powershell
.\install-service-2.3.2.ps1 -Mode Plan
.\install-service-2.3.2.ps1 -Mode Install -ServiceExecutable .\MulinSenRelayService-2.3.2.exe
```

`Install` 会核对发布者签名和固定证书指纹，备份已有服务文件，将当前用户保存的共享密钥直接转换成机器级 DPAPI 加密配置，并把服务注册为手动启动；此时不会抢占桌面版监听端口。确认提示成功后，在桌面版托盘选择“退出”，再执行：

```powershell
.\install-service-2.3.2.ps1 -Mode Activate
.\install-service-2.3.2.ps1 -Mode Status
```

看到服务为 `Running` 且状态包含 `Healthy` 后，服务将在电脑重启后由 LocalService 延迟自动启动，无需用户登录。需要恢复桌面版时执行 `-Mode Rollback`；需要删除服务注册时执行 `-Mode Uninstall`。卸载会保留机器加密配置和备份，便于恢复。

1. 查看总状态和异常提示，确认是否存在矿场离线、服务异常或线路问题。
2. 查看矿场最近心跳、客户端版本、矿机数和连接数。
3. 查看 Share 接受、拒绝情况。仅有连接不代表矿机已经正常提交计算结果。
4. 有异常时记录发生时间、矿场名称和页面提示，交由管理员处理。公网只读页面不提供修改或修复按钮。
5. 管理员在 Tailscale 面板查看“日志”页的中文处理建议，再按需要核对服务和原始日志。

VPS 自动恢复只处理系统已定义的服务异常，不等于能自动解决所有网络、矿池、电脑或配置问题。Windows 客户端的“一键诊断”用于检查矿场端网络、端口和主备 VPS，不能代替 VPS 管理权限。

## 新增矿场或值守电脑

入口：**Tailscale 管理面板 → 设置 → 客户端接入资料**。

1. 在“新增矿场 / 新增客户端”填写名称，例如“云南一号矿场（电脑1）”。
2. 点击“新增矿场并生成接入密钥”。编号和独立密钥由系统生成。
3. 在新增行复制共享密钥；本页同时提供 VPS 地址、TLS 端口和证书 SHA-256 指纹。
4. 将这些资料填写到新电脑的木林森中转，对应到正确的主 VPS 或备用 VPS。
5. 运行连接测试，成功后保存并启动中转。
6. 在矿场总览确认心跳、矿机状态和 Share。首次接入前显示“等待首次连接”。

每台值守电脑建议使用独立密钥。共用密钥会合并矿场统计，并使删除该密钥的影响扩大到所有使用者。两台 VPS 分别管理密钥，需要分别新增并填写各自接入资料；线路同步不会代替这一步。

## 修改矿场名称

1. 在接入资料页找到目标行，点击名称下方的“编辑矿场名称”。
2. 填写名称并保存。
3. 刷新管理总览或 HTTPS 只读面板，核对显示名称。

修改名称保留原编号和密钥，不需要重新配置客户端。

## 删除不用的矿场

**删除可能导致矿场中转掉线。先停用对应电脑，或完成迁移并确认矿机已在新客户端正常提交 Share。**

1. 在接入资料页找到目标行，点击“删除矿场”。点击此入口只打开确认页，不执行删除。
2. 核对矿场名称、编号、当前连接数、最近来源和最近连接时间。
3. 手动完整输入矿场名称。
4. 勾选“我已确认该矿场已停用或迁移，并了解原密钥将无法重新连接”。
5. 点击“确认删除该矿场及接入密钥”。不确定时选择“取消，保留矿场”。

确认页有效期为 5 分钟；名称或密钥发生变化后需要重新确认。删除结果如下：

- 原密钥不能建立新连接或重连；已有连接可能暂时继续，不代表后续仍能使用。
- 不重启整个中转服务，不删除其他矿场的配置，也不自动删除另一台 VPS 的接入资料。
- 操作记入审计日志，不记录密钥。保存前保留一份仅 root 可读的配置恢复副本。
- 重新新增会生成新密钥，旧电脑必须重新填写资料。
- 最后一个矿场也可删除；加密入口保持运行，等待重新添加客户端。

误删后应联系维护人员处理配置恢复，或重新新增并更新客户端资料；不要反复重启整套服务。

## 找回连接资料与修改密码

- **重装或更换 Windows 电脑**：通过 Tailscale 打开接入资料页，核对对应矿场后复制资料。密钥默认隐藏，查看或复制记入审计，查看后 60 秒自动隐藏。
- **修改 HTTPS 值守账号或密码**：由维护人员在 VPS 重新运行状态网站安装脚本并传入 `--reset-login`，详见[HTTPS 只读面板配置](deployment-guide.md#54-不使用-tailscale-的-https-只读面板)。
- **Tailscale 不可用**：可使用 SSH 隧道和预先设置的应急密码；客户端接入资料仍要求通过 Tailscale 访问。

共享密钥、密码、Webhook 和证书私钥不要发到公开群、Issue 或仓库中。证书指纹是公开校验信息，与共享密钥不同。

## 查看双 VPS 同步结果

入口：**Tailscale 管理面板 → 设置 → VPS 双向同步**。

- 修改单个线路、应用整组模板、切换到已验证线路或恢复历史线路后，页面会立即等待对端确认。
- 显示“同步成功”表示对端已经接收并处理，不只是加入等待队列。
- 显示“同步失败”或“部分成功”时，本机线路修改已经完成；页面会显示失败原因和待重试数量，后台继续自动重试。
- 设置页长期显示最近同步结果、反馈时间、待重试任务和已确认端口。后台重试成功后，最近结果会更新为成功。
- 初次配置时，只在确认线路正确的 VPS 上点击“立即同步本机全部线路”，不要在两台 VPS 上同时点击。

## 配置通知渠道

入口：**Tailscale 管理面板 → 设置 → 通知渠道**。企业微信机器人、钉钉机器人和收件邮箱均可分别设置 0–3 条；一次异常会发送给全部已配置目标。

1. 填写需要使用的渠道。机器人地址保存后不回显，每一条都可以单独删除；钉钉启用加签时，在对应机器人下填写 `SEC...` 密钥。
2. 邮件可以选择“由本 VPS 直接发送”或“使用邮箱服务商 SMTP”。VPS 直发只填写收件邮箱；SMTP 模式填写服务器、端口、加密方式、发件地址和授权码。
3. 保存后分别点击“测试企业微信”“测试钉钉”或“测试邮箱”。只有全部目标都收到测试消息后才视为配置完成。
4. 每台 VPS 分别设置通知渠道。线路同步不会复制密码、Webhook 或邮箱授权码。

VPS 直发不需要发件邮箱账号或密码，系统会自动生成发件标识。它依赖服务器能够访问收件方的 TCP 25 端口；部分云厂商会封锁该端口，没有正确的反向 DNS（PTR）、SPF 和 DKIM 时邮件也可能进入垃圾箱。出现这种情况时改用邮箱服务商 SMTP。最新版一键安装和升级脚本会安装仅监听本机的邮件投递服务，不会把 SMTP 端口开放到公网。

通知配置只允许通过 Tailscale 修改，保存在 VPS 的受限配置文件中。发送失败不会中断矿机转发，事件仍会记录在管理面板日志中。矿场离线和恢复默认各需连续确认两轮；同一矿场的同类通知 10 分钟内只发送一次。重复填写的同一机器人地址或邮箱只发送一份。建议至少配置两个不同渠道；使用 SMTP 时应使用专用授权码，不要填写邮箱登录主密码。

## 常用词说明

| 名称 | 含义 |
| --- | --- |
| 矿机数 | 按局域网 IP 识别的矿机数量；同一台矿机可能建立多条连接 |
| 连接数 | 当前中转连接数量，与矿机数不同 |
| Worker | 矿池账号下的矿工标识，不一定与矿场名称相同 |
| Share | 矿机提交给矿池的计算结果，可接受或被拒绝 |
| 心跳 | 客户端定期上报的状态，用于判断最近是否在线 |
| 证书指纹 | 客户端用于确认 VPS 证书的公开校验值 |
| 共享密钥 | 允许客户端接入对应 VPS 的秘密凭据 |

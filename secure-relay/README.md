# 木林森 Windows 客户端与 TLS 中转服务

> 功能概览和一键安装见[项目首页](../README.md)。从 VPS 到 Windows 值守电脑和矿机的配置顺序见[部署与维护指南](../docs/deployment-guide.md)。本页补充 TLS 服务和 Windows 客户端的功能细节。

这套组件在值守 Windows 电脑和 Stratum V3 VPS 之间建立 TLS 1.2 加密连接。局域网矿机仍使用普通 `stratum+tcp`，但这段明文只存在于矿场局域网内；流量卡网络只能看到电脑到 VPS 的 TLS 连接。

长期使用建议在“VPS 地址”填写域名，例如 `relay1.mulinsen.win`，以后换 VPS 时只需要修改 Cloudflare 的 DNS 记录。Cloudflare 的中转记录必须使用“仅 DNS（灰色云朵）”。完整步骤见 [域名与 Cloudflare 新手说明](../docs/cloudflare-domain-guide.md)。

```text
矿机 --局域网明文 Stratum--> 值守电脑 --TLS--> VPS --现有 V3 检查器--> 矿池
```

## 1. VPS 安装

先部署原有 Stratum V3，再执行：

```bash
cd /root/stratum-v3/secure-relay/server
chmod +x install-secure-relay.sh
./install-secure-relay.sh --port 452
```

本文使用 TCP `452`，避免和 Tailscale Serve 的 HTTPS 服务混淆。脚本会生成自签名证书和第一组 64 位共享密钥，并输出客户端需要填写的证书 SHA-256 指纹。重复执行会保留已有证书和全部客户端密钥；如果不传 `--port`，首次安装的默认端口仍为 TCP `443`。

升级已有 VPS 时也必须重新运行完整安装脚本，不要只把新版 `stratum_secure_server.py` 复制到 `/opt`。安装脚本会同步程序、systemd 权限和状态目录，并自动保留当前 TLS 端口、证书及客户端密钥。服务端即使暂时无法写入状态文件，也只会暂停心跳状态记录，不会再中断矿机转发。

完整 V3 安装生成的实际检查器配置是 `/etc/stratum-inspector.json`。确认 VPS 能接收客户端传来的矿机局域网 IP：

```bash
grep -n '"proxy_protocol": true' /etc/stratum-inspector.json
```

安全中转安装脚本也会自动执行这项检查；未启用时会停止安装并提示先重新运行 `monitor-panel/install-v3.sh`，避免矿机连接后丢失来源 IP。

如果已有正规域名证书：

```bash
./install-secure-relay.sh \
  --cert /etc/letsencrypt/live/relay.example.com/fullchain.pem \
  --key /etc/letsencrypt/live/relay.example.com/privkey.pem
```

还需在云厂商安全组中放行脚本所用的 TCP 端口。检查服务：

```bash
systemctl status stratum-secure-relay --no-pager
journalctl -u stratum-secure-monitor -n 100 --no-pager
journalctl -u stratum-secure-relay -n 100 --no-pager
```

### 每台值守电脑使用独立密钥

不要在多个矿场重复使用同一密钥。为每台值守电脑创建一组密钥：

```bash
stratum-relay-client add mine-a "一号矿场"
stratum-relay-client add mine-b "二号矿场"
stratum-relay-client list
```

`add` 输出的 `Shared key` 只填到对应电脑。某台电脑需要换密钥时执行：

```bash
stratum-relay-client rotate mine-a
```

旧密钥会立即失效。电脑停用时执行 `stratum-relay-client disable mine-a`，恢复时执行 `stratum-relay-client enable mine-a`。服务端会自动重新读取密钥文件，不需要重启。

如果以后更换 Windows 值守电脑，可以通过 Tailscale 打开 V3 管理面板，在“设置 → 客户端接入资料”中重新复制 TLS 端口、证书指纹和对应客户端的共享密钥。共享密钥默认隐藏，查看和复制都会留下审计记录。证书私钥只保存在 VPS，Windows 客户端不使用，管理面板也不会显示或提供下载。

### 矿场离线告警

客户端每 30 秒发送一次经过认证的心跳。连续 180 秒没有心跳后，`stratum-secure-monitor` 还会连续确认两轮，再发送离线告警；恢复也需连续确认两轮。同一矿场、同一类通知在 10 分钟内只发送一次，避免监控重启或状态抖动造成重复提醒。可以编辑 `/etc/stratum-secure-relay.json` 中的 `offline_after_seconds`、`offline_confirm_checks`、`recovery_confirm_checks` 和 `notification_dedup_seconds` 调整这些参数，修改后重启监控：

```bash
systemctl restart stratum-secure-monitor
```

公网 TLS 入口由专用的 `stratum-relay` 系统账户运行。它只拥有绑定低端口的能力；配置、证书和私钥为组只读，只能写入 `/var/lib/stratum-secure-relay`。已有 VPS 运行最新版 `monitor-panel/upgrade-v3-panel.sh` 时会自动完成权限迁移。

### 连接容量与矿场配额

入口有两个独立的上限，都在 `/etc/stratum-secure-relay.json` 里，改完重启生效：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `max_connections` | `20000` | 所有矿场、所有端口加起来同时在线的 TLS 连接总数。这是防滥用兜底，不是单场容量 |
| `max_site_connections` | `6000` | 单个矿场的连接上限。超出时只拒绝该矿场的新连接，其他矿场不受影响 |

分开设两个值是有原因的。**1000 台矿机、每台最多 5 条连接，一个矿场峰值就是 5000 条。** 旧版本只有一个全局 `max_connections: 1000`，等于一个场地就能占满全部名额，把其他矿场一起挤掉——而且它在认证之前就判断，被关掉的连接连是哪个矿场都看不出来。现在全局上限退为兜底，真正的容量按矿场算。

某个矿场达到自己的上限时，入口会：

- 只关闭**该矿场**的新连接，返回 `HTTP/1.1 503`，其他矿场继续正常工作；
- 在日志里写明矿场编号、名称、来源 IP 和上限值；
- 把 `exhausted_at` 和 `exhausted_limit` 写进 `/var/lib/stratum-secure-relay/sites.json`，便于事后确认是哪个矿场被限流、什么时候。

本机看门狗的健康检查走回环地址，**不计入任何矿场配额**，所以即使入口满载，监控也不会误报矿场离线。

调整示例——两个各约 1000 台的矿场，并留出余量：

```bash
python3 - <<'PY'
import json
path = "/etc/stratum-secure-relay.json"
data = json.load(open(path, encoding="utf-8"))
data["max_connections"] = 30000        # 全局兜底
data["max_site_connections"] = 6000    # 单场
json.dump(data, open(path, "w", encoding="utf-8"), ensure_ascii=False, indent=2)
PY
systemctl restart stratum-secure-relay
```

升级脚本会保留这两个值，不会把手工调整过的容量重置回默认。服务端的文件句柄上限已经是 `LimitNOFILE=65536`，两个值合起来不要超过这个数。

### 服务端下发运行参数

值守电脑的配置只保留**身份**：VPS 地址、TLS 端口、证书指纹、共享密钥。端口列表和心跳间隔这类**会变的运营参数由 VPS 下发**，改一处即对全场生效，不需要逐台改配置。

VPS 侧在 `/etc/stratum-secure-relay.json` 里配置：

```json
"runtime_settings": {
  "health_check_minutes": 1,
  "ports": "9999,10001,10002,10010,10011,10012,10020,10021,10022,10030,10031,10032,11001,11002,11003,11101,11102,11103,11201,11202,11203,11301,11302,11303"
}
```

客户端每次心跳（认证通过后）会收到两个响应头，并据此采用新值：

| 响应头 | 含义 | 生效时机 |
| --- | --- | --- |
| `X-Setting-Health-Check-Minutes` | 心跳/探测间隔（1–1440 分钟） | **立即**，下一次心跳就按新间隔 |
| `X-Setting-Ports` | 本地监听端口（支持 `9999` 与 `10041=10001` 两种写法） | **重启中转后**生效，避免运行中重绑端口导致矿机掉线 |

取值规则：

- 只接受**合法**值。`health_check_minutes` 必须在 1–1440 之间，其余写法（`0`、`-5`、`1441`、`abc`）**整条丢弃**，客户端沿用本地值——不做静默改写，因为"猜一个数"正是历史上把心跳填成 1440 分钟的成因。
- 端口列表只允许数字、`,` 和 `=`，且必须以数字开头结尾；不合法就整条丢弃，避免把客户端带到起不来的状态。
- 客户端只在**健康循环**里采用这些参数。一键诊断、配置验证、连接测试等只读流程不会改写生产配置。
- 相同值不会重复写盘。

> [!IMPORTANT]
> **本节的客户端部分需要新版 Windows 客户端才能生效。** 当前已发布的 `2.3.13` 不识别这两个响应头，会直接忽略。所以在发出新版客户端之前，部署这一版服务端是**安全但无效果**的——它只是把参数准备好。

### 更改 TLS 端口

例如把 TLS 入口改为 `8443`：

```bash
cd /root/stratum-v3/secure-relay/server
./install-secure-relay.sh --port 8443
```

脚本会保留原来的共享密钥和自签名证书，更新端口并重启服务。随后在云厂商安全组和 VPS 防火墙中放行 TCP `8443`，再把 Windows 客户端的“TLS 端口”改成 `8443`。确认新端口正常后，才关闭旧端口的安全组规则。

## 2. Windows 客户端

运行已发布并验证签名的木林森中转正式版，填写：

- VPS 地址和 TLS 端口；
- 自签名证书填写安装脚本输出的 SHA-256 指纹；使用正规证书时填写证书域名；
- 安装脚本输出的共享密钥；
- 本地监听地址保持 `0.0.0.0`；
- 只保留实际需要的转发端口。

点击“启动中转”。Windows 防火墙第一次提示时仅允许专用网络。然后将矿池地址改为界面“矿机填写地址”显示的完整地址。

2.0 增加了主 VPS 和两个备用 VPS。2.1.5 在主、备用 VPS 设置旁增加了真实连接测试，并支持自定义自动探测间隔。2.1.6 在主窗口标题中直接显示版本号，并让“矿机状态”“备用 VPS 设置”等窗口统一使用木林森程序图标。2.2.0 增加一键诊断、客户端版本上报和 VPS 端矿场分组。2.2.1 对不可达或只连接不响应的备用 VPS 增加完整认证响应超时，限制同时建立 VPS 连接的数量，并限制日志、Share历史和待确认记录的内存占用。后台网络任务不再集中占用界面线程；如果出现未处理异常，程序会记录到本机 `crash.log` 并在退出后自动重新启动，10分钟内最多恢复3次以避免故障循环。测试会完整验证 TCP、TLS证书和共享密钥，并显示成功、失败原因、响应时间和检测时间。点击“备用 VPS 设置”，每个标签页都可以分别填写启用状态、VPS 地址、TLS 端口、证书名称、证书 SHA-256 和独立共享密钥。新矿机连接会先尝试主 VPS；主 VPS无法连接、证书不符、密钥无效或没有对应路线时，依次尝试备用 VPS。主 VPS 恢复后，之后建立的新连接会重新优先使用主 VPS，已经稳定运行的连接不会被强制切断。

点击主界面的“一键诊断”，客户端会生成包含电脑与局域网、生产状态、矿机数量、主备 VPS 检测和管理员结论的文本报告。报告自动保存在 `%LOCALAPPDATA%\StratumSecureRelay`，也可以复制或另存为。报告不包含共享密钥、证书私钥或矿池密码。

### 矿机状态与估算算力

点击“矿机状态”可以查看当前及最近连接过的矿机。程序按局域网 IP 合并，同一个 IP 建立的多条连接只显示为一台矿机。列表包含：

- 健康度、当前连接数、使用线路和本地端口；
- 矿工名以及固件在 Stratum 订阅中上报的软件/型号标识；
- 首次连接、最近活动、上下行流量、断线和连接失败；
- Share 提交、接受、拒绝、拒绝率和平均响应时间；
- 10 分钟、1 小时、24 小时估算算力。
- 选择离线矿机后可删除旧 IP 记录，也可以一次清理离线超过 24 小时的记录；正在连接的矿机不会被误删。
- 矿机状态窗口不会自动重排数据，点击“刷新”时才读取最新状态；每个表头都可以点击排序，再点一次切换为反向排序。

估算算力使用已接受 Share 的难度和观察时间计算，口径为 `难度合计 × 2^32 ÷ 秒数`。它会受 Share 随机性影响，短时间数据可能明显波动，也不等同于矿机芯片直接上报的瞬时算力。程序必须收到标准 Stratum `mining.set_difficulty`、`mining.submit` 和响应消息才能计算；最近 24 小时的 Share 历史每 30 秒保存，程序正常重启后可以继续累计。

### Windows 自动启动

2.3.0 同时提供原桌面版和独立 Windows 服务。桌面版仍可勾选“开机自动启动”，在用户登录后运行；需要无人值守时，使用发布页中的签名服务 EXE 和签名安装脚本。安装分为“准备”和“激活”：准备阶段迁移机器级加密配置并保持服务停止，退出桌面版后再激活 LocalService 延迟自动启动。安装失败会恢复原服务文件、配置和桌面版开机启动设置，具体步骤见[管理员指南](../docs/administrator-guide.md#windows-无人值守服务)。

### 内部自签名代码证书

项目使用 `CN=木林森中转` 的内部代码签名证书。签名私钥为不可导出，只保存在发布电脑的 Windows 证书库；`client/src/signing/木林森中转-内部代码签名证书.cer` 是不含私钥的公开证书，可以复制到矿场电脑。

新矿场电脑首次使用时，以管理员身份运行 `client/src/signing/安装木林森内部签名证书.ps1`。安装脚本会先核对固定证书指纹，再把公开证书加入本机的“受信任的根证书颁发机构”和“受信任的发布者”。以后只接受发布者为“木林森中转”且数字签名有效的 EXE。若电脑不再使用本程序，可以运行同目录的移除脚本撤销信任。

发布电脑生成最终程序时使用：

```powershell
.\build.ps1 -Sign
```

测试版使用 `.\build.ps1 -TestBuild -Sign`。必须先完成编译再签名；签名之后对 EXE 的任何修改都会使数字签名失效。公开证书可以备份和分发，私钥、PFX、PVK 和 KEY 文件禁止上传 GitHub。内部自签名主要解决自有电脑的发布者信任问题，不能保证 Defender 云端模型不误报。

“开机自动启动”和“点击关闭最小化”可以分别启用或关闭。设置完成后点击“保存设置”。软件内的“各项说明”按钮也可以随时查看通俗解释。

软件会自动识别值守电脑当前的局域网 IP，并根据“本地端口”生成完整的矿机填写地址。例如电脑 IP 是 `192.168.3.5`、本地端口是 `9999`，界面会显示：

```text
stratum+tcp://192.168.3.5:9999
```

多个端口会生成多个地址，可以在下拉框中选择并点击“复制地址”。IP 每30秒自动刷新，也可以手动点击“刷新”。

## 各个设置是什么意思

当前源码版本 `2.3.0` 在完成中转核心拆分的基础上新增 Windows 服务和独立看门狗。服务使用 LocalService 账户、机器级 DPAPI 与受限 ACL；进程退出或完全无响应时连续复查后恢复，10 分钟内三次恢复仍失败则锁定并说明原因。开发与验收记录见[路线计划](../docs/improvement-roadmap.md)和[服务设计](client/src/SERVICE-DESIGN.md)。

- **VPS 地址**：填写 VPS 公网 IP 或中转域名。正式运行推荐域名，例如 `relay1.mulinsen.win`；不要填写 `https://`、端口或结尾斜杠。
- **TLS 端口**：VPS 接收加密连接的门牌号，通常使用 `443`。
- **证书名称**：如果 VPS 使用正规域名证书，这里填写证书对应的域名。只使用 IP 和自签名证书时留空。
- **证书 SHA-256**：服务器证书的唯一指纹。它帮助软件确认对面确实是你的 VPS，防止连接被冒充。
- **共享密钥**：客户端和 VPS 共同知道的密码。密钥错误时，VPS 会拒绝连接。
- **本地监听地址**：保持 `0.0.0.0`，表示允许同一局域网内的矿机连接这台值守电脑。
- **端口或端口映射**：`9999` 表示矿机连接本地 `9999`，VPS 也走 `9999` 路线；`10041=10001` 表示矿机连接本地 `10041`，VPS 按 `10001` 路线转发。多个项目仍用英文逗号分隔，本地端口不能重复。
- **当前局域网 IP**：程序自动识别值守电脑连接矿机局域网的 IPv4 地址，并排除 Tailscale、代理和常见虚拟网卡。
- **矿机填写地址**：将局域网 IP、本地端口和 `stratum+tcp://` 自动组合成完整地址，可以直接复制到矿机后台。
- **开机自动启动**：值守电脑登录 Windows 后，软件自动打开并启动中转。
- **关闭时最小化到托盘**：点击窗口右上角关闭按钮后，软件继续在后台运行；取消此项后，点击关闭会退出软件并停止中转。
- **运行记录**：显示哪些矿机连上、断开或发生连接错误，方便值守人员判断运行状态。

- **测试主VPS / 测试这台VPS**：不依赖矿机，直接完成TCP连接、TLS证书和共享密钥认证；全部通过才显示正常。

- **VPS自动探测间隔**：中转运行后，按设定的分钟数检测所有已启用线路。主界面持续显示每条线路的最近结果、延迟、错误和检测时间。
- **状态栏**：“当前矿机”按在线的唯一局域网 IP 统计，“当前连接”保留矿机产生的实际连接数量；同时显示累计连接、失败次数、运行时间、上下行流量以及每台 VPS 的可用状态和延迟。
- **矿机状态**：相同局域网 IP 合并为一台矿机，可查看连接健康度、Worker、固件标识、Share 质量和三个时间窗口的估算算力；双击一行可查看检修详情。

## 三台 VPS 的准备方法

主 VPS 和备用 VPS 都必须先部署相同的 Stratum V3 路线，再安装本目录的安全中转服务。三台 VPS 的端口路线应保持一致，这样客户端切换线路时，同一个 VPS 路线端口仍指向同一个矿池。每台 VPS 分别为这台值守电脑创建独立密钥，客户端的三个 VPS 页面分别填写各自服务器输出的密钥和证书指纹。

如果暂时只有一台 VPS，备用线路保持未启用即可，不影响现有用法。

例如原地址为 `stratum+tcp://203.0.113.10:9999`，值守电脑地址为 `192.168.1.20`，矿机改填：

```text
stratum+tcp://192.168.1.20:9999
```

## 安全和识别边界

- 共享密钥在 Windows 上由当前用户的 DPAPI 加密保存，VPS 配置权限为 `0600`。
- 客户端强制验证正规证书或固定 SHA-256 指纹，不提供跳过证书验证的选项。
- 未认证连接只得到普通 HTTPS 404 响应；矿池协议和认证字段始终位于 TLS 内。
- 网络仍能观察 VPS IP、连接时长、流量大小和时序。因此 TLS 能隐藏 Stratum 内容，但不能保证任何网络环境都无法识别或限制该连接。
- 自签名证书可以安全固定身份，但正规域名证书的 TLS 外观更常见。域名的 SNI 仍可能被网络看到。

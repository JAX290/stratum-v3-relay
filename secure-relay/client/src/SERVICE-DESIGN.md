# WIN-P01 服务与看门狗：分阶段验收

状态：2026-09-21，WIN-P01 已完成。2.3.0 包含恢复策略、持久化互斥、服务宿主、独立工作进程、机器级加密迁移和分阶段安装回退。管理员权限下的隔离服务完成真实 SCM、LocalService、崩溃恢复、安装失败回退和电脑重启验收；未迁移生产配置。

## 已实现的恢复策略

`RecoveryPolicy.cs` 独立计算恢复决策，不连接服务器、不启动或终止进程。当前不编入正式桌面程序；由 `test-client.ps1` 单独编译测试。

- 新进程有 60 秒启动宽限期；使用进程启动后的本地心跳判定响应。
- 至少 3 次异常检查、检查间隔至少 10 秒，才允许恢复。
- 每次恢复间隔至少 60 秒；10 分钟最多 3 次，继续失败则锁定停止。锁定不会随时间流逝自动解除。
- 必须先调用持久化接口保存本次预算，再返回恢复决定。持久化失败或接口缺失时停止恢复。
- 人工停用优先，重新启用不会直接沿用之前的连续异常计数。
- 状态通过序列化可恢复；记录缺失、格式版本不支持或时间倒退时停止自动恢复。
- 对外中文提示不包含原始异常，避免将路径或敏感资料带入说明。

29 项测试验证上述边界，包括序列化后仍保留停止保护、旧进程心跳、重复轮询、预算窗口、保存异常与快照隔离。完整客户端和无界面核心原有各 25 项回归仍通过。

## 后续集成的硬性要求

1. 看门狗必须独立于中转进程，并监测核心工作线程可完成的本地健康请求。单独定时器仍在跳动不能证明中转核心未卡死；矿池不可达或暂时没有 Share 也不能直接认定程序卡死。
2. 恢复策略只由一个串行调用者持有。服务运行实例与状态文件必须使用跨进程锁；持久化接口要同步完成原子保存和历史备份后才返回，失败必须抛出异常。不能用异步排队或吞掉异常来代表保存成功。
3. 每次启动看门狗均加载现有预算，只有首次安装能创建空记录。停止保护需管理员明确解除，不能通过重启看门狗清空。恢复动作失败也消耗已经保存的次数。
4. 终止目标使用已经验证的进程句柄及启动身份，防止 PID 被复用后误杀其他程序。人工停止服务时先禁止恢复，再停止中转。
5. 当前 DPAPI 使用用户作用域，服务账户不能直接读取另一用户的共享密钥。独立安装流程需要在原用户上下文中解密，采用服务专用受限存储，并验证文件权限；禁止明文落盘、传入命令行或写入日志。
6. 安装、升级、停用及恢复桌面版需提供中文操作入口、签名验证、配置备份、执行后检查和失败回退。原桌面程序仍能安全恢复使用。
7. 完成无登录启动、重启电脑、进程崩溃、完全卡死、连续失败停止和安装回退实机验收后，才能将 WIN-P01 标为已完成。

## 本阶段实现与验证

- `RelayServiceHost.cs`：独立 ServiceBase 宿主；看门狗在固定线程持有恢复记录租约。工作进程启动后读取服务专用配置，中转本地健康检查通过线程池和状态锁完成，并核对监听套接字。停止命令会禁止后续恢复。
- `WorkerProcess.cs`：独立子进程，先加入 Windows Job Object 后才发送 GO。心跳采用递增请求编号，拒绝不匹配的响应；不使用任意 PID 终止目标。正常停止先请求退出，超时再关闭所属 Job；监督进程异常退出时由系统清理子进程。
- `WatchdogSupervisor.cs`：将恢复决策接到真实进程创建和终止；启动失败消耗已保存的预算，连续失败停止。
- `ServiceConfiguration.cs`：在内存中转换配置，使用 LocalMachine DPAPI 加密；不写明文、不改变桌面密钥，导入时校验监听、端口、证书身份和共享密钥。机器作用域加密必须配合受限目录 ACL，不能独立替代访问控制。
- `ServiceInstallerData.cs`：由保存桌面配置的用户解开 CurrentUser DPAPI，再直接写成 LocalMachine DPAPI；共享密钥不进入命令行、日志或明文文件。重复准备不会清空已有恢复预算。
- `install-service.ps1`：先核对正式签名和固定证书指纹，再创建受限目录、备份、迁移和验证配置，最后以手动模式注册服务。桌面版退出后单独激活延迟自动启动；失败会恢复原 EXE、配置、恢复预算及桌面版开机启动。脚本使用 UTF-8 BOM，兼容 Windows PowerShell 5。
- `build-service.ps1 -OutputDirectory <临时目录>`：编译开发组件。测试入口同时验证桌面程序、无界面核心、恢复基础及服务开发组件，不覆盖历史 EXE。

本地 127 项检查通过：桌面及无界面核心各 28 项，恢复策略、存储、服务运行和安装计划共 71 项。其中真实子进程测试验证心跳、退出、无响应、限定时间内终止，以及监督进程崩溃后的子进程清理；完整重启预算流程使用受控时间和模拟进程，避免等待生产冷却时间。

隔离实机验收已通过：测试专用签名 EXE 经正式安装脚本迁移配置并注册到 SCM；服务账户为 LocalService；启动类型可设为自动；本地健康检查通过；强制结束工作进程后按连续探测和冷却策略拉起；人工停止后保持停止。验收还故意输入损坏桌面配置，确认安装失败后原服务 EXE、机器加密配置和恢复预算 SHA-256 均保持不变。测试服务、目录和临时证书在结束时删除。

电脑重启验收中，系统启动时间晚于准备标记，服务 PID 从 `46148` 变为 `26556`；SCM 以 LocalService 自动启动新服务进程及独立工作进程，并在本次启动后重新写入 Healthy。隔离服务、目录和标记随后全部清理。正式发布只接受代码签名有效且指纹固定的服务 EXE；测试组件不得替换正式桌面或服务程序。

实现依据：[Windows Job Objects](https://learn.microsoft.com/zh-cn/windows/win32/procthread/job-objects)、[ServiceBase.OnStop](https://learn.microsoft.com/en-us/dotnet/api/system.serviceprocess.servicebase.onstop)。

服务控制协议已固定字节编码并独立读取 UTF-8，避免 Windows 控制台代码页和 BOM 导致启动命令失效；该修复远端 CI 已通过。新增 ServiceStoragePermissions：生成受限目录权限模板，启动前验证目录和文件权限、所有者及目录链接。普通用户可访问的配置会阻止启动；权限实际写入由后续安装流程负责。
